# Local OCR: initial WP-24/25 increment

Compound follow-up: exact known catalog titles/aliases in separate native OCR
lines are shown as bounded heading observations. Repeated headings keep separate
locations; duplicate catalog titles remain ambiguous. Coordinates are selection
image pixels, not source-PDF regions. Observations are recalculated only against
matching rule context and never create regions, editions, approval or inferred
continuations. Full booklet use and optional segmentation remain separate.
Printed heading numbers may be retained alongside an exact known title/alias;
they never establish musical identity. Exact numeric titles take precedence over
prefix stripping. Repeated song numbers across booklets remain independent.

From a published version's review page, **Alle Seiten lokal mit OCR analysieren**
enqueues the existing OCR job. The normal single-heavy-worker runner processes
each source page, publishes progress and supports the existing cancellation UI.
Confirmed unchanged versions may be reanalysed without changing their approval,
musical assignments, inspection or historical exports. A derivative cannot be
silently treated as its original source.

Only verified byte-identical CLEAN publications are read. The processor stages
private copies, applies the exact original page geometry and renders at the
configured 100–300 DPI. OCR runs even when a text layer exists. Tesseract 5.5.2-r0
and German/English language packs are pinned in the Alpine container. LSTM-only
OCR uses at most two OpenMP threads, 384 MiB process memory and 60 seconds per
page. PDF processing retains its independent pixel/output/CPU limits. No text
is sent externally or included in subprocess logs.

The CLI uses the existing owned process runner, not pytesseract's second
subprocess lifecycle. This small implementation choice preserves the existing
process-tree containment, cancellation and uncertain-cleanup contract; it does
not replace the approved local Tesseract technology or queue. No Python OCR
dependency is necessary. Native Windows OCR runtime distribution is not supplied
by this increment; native Windows storage writes remain disabled.

Immutable page evidence retains original hash, source page, region bounds,
orientation/revision, recognized words and rendered-selection pixel boxes,
OCR confidence, PDF text, rule version and runtime/profile identity. Reanalysis
reuses matching committed page evidence; changed rules, source, geometry or
profile produce a different cache context. Worker metadata commits remain fenced.
PDF text and raster OCR are compared independently. Contradictory known works,
instruments or part numbers remain conflicts with no proposed playable parts;
readable known text-layer metadata may supplement unresolved OCR without approval.
The installed Alpine package database additionally binds the native dependency
closure to the cache runtime identity. Restart recovery under the existing
exclusive worker authority removes only recognized owned unmarked scratch files.
An active or unsafe abandoned scratch workspace blocks further OCR pending ownership review;
uncertain process termination never proves cancellation or permits cleanup.

Selected-page/rectangle jobs use the same queue and immutable evidence model.
The queue stores a zero-based physical page and normalized top-left displayed
rectangle; the worker converts all four corners through the original CropBox,
rotation and UserUnit into canonical physical PDF points before processing.
Only that selection is OCRed. Whole-file and selected jobs are separately
idempotent; equivalent exact processing contexts reuse committed evidence.
Selections do not create musical regions or alter original page sequences.
The isolated PDF worker extracts only text geometrically inside the clipped
logical canvas, so outside headings cannot contaminate selected text evidence.
Native block/paragraph/line identities preserve side-by-side headings; legacy
word evidence retains its conservative geometric grouping fallback. Profile
`page-v3` prevents reuse of evidence generated by the earlier grouping/extraction
or incorrect rotated-canvas text bounds. Native text clipping uses unrotated
MediaBox/CropBox intersection coordinates, not displayed rotated dimensions.
Rule fingerprints include identity mappings as well as normalized labels, so
retargeting aliases or adding another equal-title work invalidates cache context.

The existing review selections allow manual correction/rejection/inspection;
OCR suggestions are never approval. Review exposes the exact selected source
image through an authenticated, no-store endpoint that verifies the publication
and source hash again. Image rendering shares the bounded preview process lock;
foreign-version evidence cannot be read through another source's URL. OCR word
confidence describes recognition, not musical approval. Independent multiple-work
proposals, complete booklet continuation analysis and graphical segmentation
remain subsequent increments, not delivered WP-26/56 acceptance.
The subsequent region-editor batch adds explicit **unconfirmed** rectangle saves
from the same source viewer. These are separate from transient OCR selections:
the archivist deliberately saves a new stable region, or loads a saved region
and appends a revision. The service requires retained original page geometry,
verified BASE bytes, current file/version pins and the expected region revision.
It rechecks publication availability under the SQLite writer fence. Missing
legacy original geometry is rejected rather than silently reconstructed.
Saved regions are bounded to the latest 20 on the review page; selection stays
disabled during PDF initialization/rendering. Saving never creates musical
assignments, inspection, confirmation, logical editions or new export eligibility.
Prior region revisions and historical logical-page pins remain unchanged.
Reordering, merging, sequence preview and musical confirmation workflows remain
open WP-56 scope. This editor batch still requires its own exact-head CI.

WP-27 integrity and WP-28 representative DS224+ measurements remain separate.
The German manual plan must not infer recognition accuracy from synthetic tests.
