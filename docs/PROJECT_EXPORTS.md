# Project excerpts, exact reprints and contents-only (WP-37c)

## Collections, movements and physical replacements

New EX-11–14 acceptance extends selected positions/participants to their confirmed
content editions. Keep the common list, contents numbering and stable occurrence
identity while allowing different instrument pagination. Whole instrumental
booklet exports belong to independent archive output, not personal project-list
changes. Distinguish standalone excerpts from insertion-compatible replacements.
The latter pin the previous final-page parity, binding and template revision,
with a blocking finding when those cannot be reproduced. Existing exact
whole-file historical output remains available. Region/collection replay and
shared-page policies require new tests after DEC-13.

Current project excerpts use the existing central resolver/preflight and WP-36b
authorization service with kind EXCERPT. Selected active positions × participants
are pinned together, in shared order with existing numbers. Personal exact editions
and compatible parts win exactly as for full folders. No project/default/list
mutation occurs. One lost individual part can be regenerated without a full folder.
The existing replacement-at-slot workflow retains position identity/number; a new
excerpt pins that slot's currently confirmed assignment. Reserve-only excerpts are
rejected because reserves produce no music. Acknowledged missing cells generate
German placeholders rather than silent omission. Excerpts default to music only,
without cover or contents. Original PDF geometry/vector content remains unchanged.

Contents-only has its own project selection report and actor-bound 30-minute signed
authorization. It pins the full shared position sequence, reserves, title, revision
and page options; no participant, resolver music, archive bytes or missing decisions
are needed. Authorization acquires SQLite's writer and rechecks the exact report.
One participant-free artifact uses the shared publication protocol and completion
inventory; nullable-participant partial constraints prevent duplicate contents outputs.
The separate German contents PDF contains project metadata/numbered titles and no
music, cover or missing placeholder pages.

Historical excerpts select people/positions from an existing immutable FULL/EXCERPT
snapshot, not the current graph. Confirmed eligible exact file hashes and relational
pins and bounded PDF structure are verified before a new actor/report-bound
authorization. Only requested pinned files are inspected; unrelated corrupted
historical music does not prevent replacing a still-valid requested part. A protected
source_snapshot reference and source fingerprint record provenance. Removed/inactive
current people/positions, new preferences/defaults or a replaced arrangement do not
substitute historical choices. Previously missing cells require fresh acknowledgement.
Unexpected missing/corrupt/invalid/withdrawn inputs block; old outputs remain untouched.
The new snapshot copies only requested person/position/input pins with original
numbers. A fresh run/path/artifact is produced; token replay reuses the authorized run.

Project and matrix link to excerpts; project also links to contents-only and a bounded
100-run navigation list for exact historical reprints. Auth, CSRF, stale signed reports
and complete-batch-only hash-verified downloads are retained. This is minimal selection
navigation for WP-37c, not WP-39's unified export library, stale classification, retention,
ZIP or print-artifact management. No printing/imposition/OCR/deployment is included.

SQLite table remakes reinstall snapshot/pinned-source/export UPDATE guards; prior
history is retained. The shared worker/staging/reconciliation/cleanup limits and
Linux-only physical publication contract remain as in PERSONAL_GENERATION.md.

slot replacement, removed historical positions, contents-only, reserves/missing,
